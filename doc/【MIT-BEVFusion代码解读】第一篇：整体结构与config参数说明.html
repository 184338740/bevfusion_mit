1. 结构简介

模型BEVFusion，内部包含四个模块。encoder、fuser、decoder和head。它们之间的流程图如下所示。

下面就这四部分的主要参数进行简要说明，具体的流程会在后续的文章展开。

（1）encoder模块

encoders的作用是将相机和点云特征转化为BEV特征。它的配置参数如下：

  • lidar的encoder

lidar的encoder主要有两部分，分别是voxelize和backbone，其中backbone部分使用的是SparseEncoder方式。

  • camera的encoder

camera的encoder主要有3部分，分别是backbone、neck和vtransform部分。其中backbone使用SwinTransformer，neck使用GeneralizedLSSFPN，vtransform部分使用的是DepthLSSTransform，如下所示。

（2）fuser模块

fuser模块的作用是将LiDAR和camera提取的BEV特征进行融合，这里使用ConvFuser方法将特征进行融合。实际上也就是进行concat，然后再卷积提取特征的融合方法。

  fuser:
    in_channels:
    - 80
    - 256
    out_channels: 256
    type: ConvFuser

（3）decoder模块

decoder分为backbone和neck部分，backbone使用的是SECOND，neck部分使用的是SECONDFPN。

（4）head模块

我们这里主要介绍的是目标检测部分，所以head的部分输出为center、dim、height、rot、vel。

其中回归loss使用的是L1Loss、类别分类使用FocalLoss，heatmep部分使用的是GaussianFocalLoss。

2. 加载参数方式

BEVFusion中使用的是torchpack.utils.config和argparse进行参数加载，其中argparse在运行脚本命令的时候添加参数，而torchpack.utils.config它除了加载指定的yaml或yml格式数据外，还会进行可选的递归加载上层目录的default.yaml格式数据。

BEVFusion的代码采用的就是递归的方式加载参数，如下所示。

configs.load(args.config, recursive=True) # recursivet递归加载参数
configs.update(opts)

torchpack加载参数的规则为：递归不断添加上层default.yaml中的参数，加载某个参数之前会检查某个值是否已经存在，如果存在，则不添加。换句话说，目录越深的参数，优先级更高。

3. 参数、日志保存

参数和日志会保存在args.run_dir下，如果没有通过argparse指定，则会通过torchpack.environ随机生成路径，随机生成的路径在runs/下。生成保存路径的代码如下：

    if args.run_dir is None:
    	# 如果没有手动设定保存路径run_dir，则随机生成保存路径
        args.run_dir = auto_set_run_dir()
    else:
        set_run_dir(args.run_dir)

其中输入的配置文件参数保存在configs.yaml中，日志保存在{timestamp}.log文件中，tensorboard日志保存在tf_logs下

4. 其他说明

（1）pdb断点调试

如果是使用多线程，使用pdb的方式不能正常的使用断点功能，则可以修改configs/nuscenes/default.yaml的参数，将workers_per_gpu修改为0，则不会使用多线程，那么就可以正常使用pdb进行调试了。

samples_per_gpu: 4 # 单个gpu的batch_size
workers_per_gpu: 0 # 设置pdb调试的时候，将其设置为0

（2）范围相关

  • point_cloud_range

point_cloud_range表示点云的范围，默认范围为[-51.2, -51.2, -5.0, 51.2, 51.2, 3.0]。相对应的范围与读入的数据集点云顺序有关，一般为激光对应的x、y和z的最小和最大范围值。

  • image_size

image_size也就是图片大小，对应的是[H, W]。

image_size: [256, 704]
  • max_voxels

max_voxels表示前传时，hard voxel的最多的voxels个数。max_voxels列表的第一元素表示train模式时voxel个数，第二个元素表示test/val模式下的voxel的个数。

# train和test时最多的voxel个数
max_voxels: [120000, 160000]

train和test/val模式切换代码如下：

        if self.training:
            max_voxels = self.max_voxels[0]
        else:
            max_voxels = self.max_voxels[1]

（3）checkpoint

保存模型的代码位于mmcv/runner/hooks/checkpoint.py中，配置如下，其中interval保存模型的间隔数，max_keep_ckpts表示最多保存的模型数，如果max_keep_ckpts=1，那么只会保存最新的一个模型，如果max_keep_ckpts=-1，那么会保留所有的模型。

  interval: 1#模型保存的间隔数
  max_keep_ckpts: 1#模型最多保留的数目，如果为负数，那么会保留所有的模型
