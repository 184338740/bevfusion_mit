import re
import matplotlib.pyplot as plt
import numpy as np

# ===================== 1. 解析日志文件 =====================
def parse_mmdet3d_log(log_path):
    """解析mmdet3d日志文件，提取train/val loss"""
    train_loss_pattern = re.compile(r'Epoch \[\d+/\d+\]  iter: \d+  lr: \d+\.\d+  loss: (\d+\.\d+)')
    val_loss_pattern = re.compile(r'Epoch \[\d+/\d+\]  val_loss: (\d+\.\d+)')
    
    train_loss_list = []
    val_loss_list = []
    with open(log_path, 'r', encoding='utf-8') as f:
        for line in f:
            # 匹配train loss
            train_match = train_loss_pattern.search(line)
            if train_match:
                train_loss = float(train_match.group(1))
                train_loss_list.append(train_loss)
            # 匹配val loss
            val_match = val_loss_pattern.search(line)
            if val_match:
                val_loss = float(val_match.group(1))
                val_loss_list.append(val_loss)
    return train_loss_list, val_loss_list

# 替换为你的日志文件路径
log_path = 'runs/train-bevfusion-det-transfusion-finetune/20251211_100000.log'
train_loss, val_loss = parse_mmdet3d_log(log_path)

# ===================== 2. 绘制Loss曲线 =====================
plt.rcParams['font.sans-serif'] = ['SimHei']
plt.rcParams['axes.unicode_minus'] = False

plt.figure(figsize=(12, 6))

# 绘制train loss（按iter）
plt.plot(range(1, len(train_loss)+1), train_loss, label='训练Loss (Train Loss)', color='blue', alpha=0.8)

# 绘制val loss（按epoch，需对齐x轴）
val_x = np.linspace(1, len(train_loss), len(val_loss))  # 均匀映射到train iter的x轴
plt.plot(val_x, val_loss, label='验证Loss (Val Loss)', color='red', linewidth=2)

plt.title('BEVFusion 训练/验证Loss收敛曲线', fontsize=14)
plt.xlabel('训练迭代数 (Iter)', fontsize=12)
plt.ylabel('损失值 (Loss)', fontsize=12)
plt.legend(fontsize=12)
plt.grid(True, alpha=0.3)
plt.tight_layout()

# 保存图片
plt.savefig('bevfusion_loss_convergence.png', dpi=300, bbox_inches='tight')
plt.show()

三、目录文件解读 & 常见问题排查
文件名	作用
20251210_220844.log	纯文本日志，包含训练 / 验证的 Loss、lr、耗时、指标等（人工查看 / 正则解析）
20251210_220844.log.json	结构化 JSON 日志，每行一个日志对象，解析更精准（无正则匹配错误）
configs.yaml	训练时 dump 的完整配置文件，可核对可视化、训练轮数、Loss 配置等
logging	mmdet3d 的日志辅助目录（无需关注）
tf_logs	TensorBoard 日志目录（核心，启动 TensorBoard 需指定此目录）
常见问题排查：
TensorBoard 无数据：
检查 tf_logs 内是否有子目录（如 events.out.tfevents.xxxx），若无则说明训练未正常记录，需核对配置中 log_config.hooks 包含 TensorboardLoggerHook；
若有子目录但 TensorBoard 无曲线，执行 tensorboard --logdir=./tf_logs --reload_interval=5 强制刷新。
日志中无 Val Loss：
核对配置中 evaluation.interval 是否 > 0（你的配置是 1）；
核对 train_model 的 validate=True（你的 train.py 已设置）；
若训练轮数仅 1 轮且未完成验证，也会无 Val Loss。
Loss 数值异常（如无穷大 / NaN）：
检查日志中是否有 NaN/inf，若有 → 学习率过高 / 数据增强异常 / 数据集标注错误；
临时解决方案：下调学习率（如从 0.0002→0.0001）、关闭部分数据增强（如 GridMask）。

远程堡垒机不支持浏览器，我可以scp到本地再执行吧？
完全可以！针对 “远程堡垒机无浏览器” 的场景，有两种更高效的方案（优先推荐端口转发，无需拷贝文件；若需离线查看则用 SCP 拷贝日志到本地），下面给出详细操作步骤：
方案 1：本地端口转发（推荐，无需拷贝文件，实时查看）
核心逻辑：通过 SSH 将远程服务器的 TensorBoard 端口（6006）映射到本地，本地浏览器访问localhost:6006即可直接查看远程的 Loss 曲线，无需拷贝任何文件。
步骤 1：本地终端执行端口转发（关键）
打开本地电脑的终端（Windows 用 PowerShell/CMD，Mac/Linux 用 Terminal），执行：
bash
运行
# 格式：ssh -L 本地端口:localhost:远程端口 用户名@远程服务器IP
ssh -L 6006:localhost:6006 mingyuan@rss-ai-dev-suz-kjc-gpu01-a100
执行后会提示输入远程服务器的密码，输入后保持该终端窗口打开（关闭则端口转发失效）；
若本地 6006 端口被占用（如本地也开了 TensorBoard），可换端口（如 6007）：
bash
运行
ssh -L 6007:localhost:6006 mingyuan@rss-ai-dev-suz-kjc-gpu01-a100
步骤 2：远程服务器启动 TensorBoard
在远程堡垒机的终端，进入日志目录并启动 TensorBoard：
bash
运行
# 进入你的日志目录
cd /data2/xmy/01_project/bevfusion_mit_xmy_1205/runs/v8.1-1210-01
# 启动TensorBoard（绑定0.0.0.0允许端口转发访问）
tensorboard --logdir=./tf_logs --port=6006 --host=0.0.0.0
若步骤 1 换了端口（如 6007），这里--port仍用 6006（因为转发的是远程的 6006 到本地 6007）。
步骤 3：本地浏览器访问
打开本地浏览器，输入：
若用默认 6006 端口：http://localhost:6006
若换了 6007 端口：http://localhost:6007
即可看到远程服务器上的 Loss 收敛曲线（实时同步，训练过程中也能看）。
方案 2：SCP 拷贝 tf_logs 到本地（离线查看）
若不想保持端口转发，可将远程的tf_logs目录拷贝到本地，本地启动 TensorBoard 查看。
步骤 1：本地终端执行 SCP 拷贝
bash
运行
# 格式：scp -r 用户名@远程服务器IP:远程目录 本地目录
scp -r mingyuan@rss-ai-dev-suz-kjc-gpu01-a100:/data2/xmy/01_project/bevfusion_mit_xmy_1205/runs/v8.1-1210-01/tf_logs /Users/你的本地用户名/Desktop/
-r：递归拷贝目录（必须加，因为 tf_logs 是目录）；
替换/Users/你的本地用户名/Desktop/为你本地的目标路径（如 Windows：C:\Users\你的用户名\Desktop\）；
输入远程密码后，等待拷贝完成（tf_logs 不大，通常几秒完成）。
步骤 2：本地启动 TensorBoard
本地终端进入拷贝后的目录，启动 TensorBoard：
bash
运行
# 进入本地tf_logs所在目录（以桌面为例）
cd /Users/你的本地用户名/Desktop/
# 启动TensorBoard
tensorboard --logdir=./tf_logs --port=6006
步骤 3：本地浏览器访问
打开本地浏览器，输入http://localhost:6006即可查看 Loss 曲线。
补充：若堡垒机是 “双层跳转”（本地→堡垒机→目标 GPU 机）
如果你的rss-ai-dev-suz-kjc-gpu01-a100是 GPU 机，且需要先连堡垒机再连 GPU 机，端口转发需用 “代理跳转”：
bash
运行
# 本地终端执行（双层端口转发）
ssh -L 6006:localhost:6006 -J 堡垒机用户名@堡垒机IP mingyuan@rss-ai-dev-suz-kjc-gpu01-a100
-J：指定堡垒机作为代理，直接跳转到 GPU 机；
后续步骤和方案 1 一致（GPU 机启动 TensorBoard，本地访问localhost:6006）。
注意事项
端口冲突：若本地 6006 被占用，可任意换端口（如 6008、8888），只需保持 “远程端口” 和 “转发的远程端口” 一致；
TensorBoard 版本：本地需安装和远程一致的 TensorBoard 版本（pip install tensorboard），避免日志解析报错；
离线绘图：若只想画静态图，也可 SCP 拷贝日志文件（20251210_220844.log）到本地，用之前给的解析代码绘制 Loss 曲线。
两种方案都能解决 “远程无浏览器” 的问题，端口转发更高效（实时 + 无拷贝），SCP 适合离线查看，你可根据需求选择。
